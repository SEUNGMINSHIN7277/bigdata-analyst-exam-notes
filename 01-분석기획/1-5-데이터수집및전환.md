### Q1-041 [난이도: 하] [태그: 1과목/데이터수집및저장계획/ETL]

ETL 프로세스의 세 단계를 수행 순서대로 바르게 나열한 것은?

① 변환(Transform) → 추출(Extract) → 적재(Load)
② 추출(Extract) → 변환(Transform) → 적재(Load)
③ 적재(Load) → 추출(Extract) → 변환(Transform)
④ 추출(Extract) → 적재(Load) → 변환(Transform)

<details><summary>정답 및 해설</summary>

**정답: ②**

- **①** 원천에서 꺼내기(추출) 전에 변환할 대상이 없으므로 순서가 성립하지 않는다.
- **②** 원천 시스템에서 **추출** → 규칙에 따라 **변환** → 목표 시스템에 **적재**. ETL의 정의 그 자체. ← 정답
- **③** 적재가 맨 앞에 오는 순서는 존재하지 않는다.
- **④** 추출 → 적재 → 변환은 ETL이 아니라 **ELT**의 순서다. 함정 선지.

**출제 포인트:** ETL은 이름의 알파벳 순서(E→T→L)가 곧 수행 순서. ④처럼 T와 L을 바꾼 선지는 ELT를 묻는 함정이다.

**근거:** ETL은 원천 데이터를 추출(Extract)하고 목표 형식에 맞게 변환(Transform)한 뒤 목표 시스템에 적재(Load)하는 데이터 수집·통합 프로세스다.
</details>

### Q1-042 [난이도: 하] [태그: 1과목/데이터수집및저장계획/수집기술매칭]

서버-클라이언트 방식으로 동작하며, 수집 대상 시스템과 1:1로 연결하여 파일과 디렉터리를 동기화(미러링)하는 데 사용되는 데이터 수집 기술은?

① 리싱크(Rsync)
② FTP
③ RSS
④ Open API

<details><summary>정답 및 해설</summary>

**정답: ①**

- **①** 리싱크(Rsync, Remote Sync): 서버-클라이언트 방식으로 수집 대상 시스템과 **1:1로 파일·디렉터리를 동기화**하는 응용 프로그램. ← 정답
- **②** FTP(File Transfer Protocol): TCP/IP 기반으로 파일을 **송수신(전송)** 하는 프로토콜. 전송이 목적이지 동기화(미러링)가 목적이 아님.
- **③** RSS(Rich Site Summary): 갱신 콘텐츠를 XML 기반으로 **배급·구독**하는 기술.
- **④** Open API: 공개된 인터페이스를 **호출**하여 데이터를 받아오는 방식.

**출제 포인트:** 파일 계열 수집 기술 구분 — FTP=파일 전송, Rsync=1:1 동기화(미러링). "동기화·미러링" 키워드가 보이면 Rsync.

**근거:** 리싱크(Rsync)는 서버-클라이언트 방식으로 수집 대상 시스템과 1:1로 파일과 디렉터리를 동기화하는 데이터 수집(응용) 프로그램이다.
</details>

### Q1-043 [난이도: 하] [태그: 1과목/데이터수집및저장계획/OpenAPI·RSS·FTP]

블로그·뉴스 사이트 등에서 새로 갱신된 콘텐츠를 XML 기반 형식으로 배급하여, 구독자가 사이트에 방문하지 않고도 갱신 정보를 수집할 수 있게 하는 기술은?

① Open API
② FTP
③ RSS
④ 크롤링(crawling)

<details><summary>정답 및 해설</summary>

**정답: ③**

- **①** Open API: 서비스 제공자가 **공개한 인터페이스를 호출**하여 데이터를 받아오는 방식. 배급·구독 형식이 아님.
- **②** FTP: TCP/IP 기반 **파일 전송 프로토콜**. 대용량 파일 송수신에 사용.
- **③** RSS: 갱신 콘텐츠를 XML 기반으로 **배급(syndication)·구독**하는 형식. ← 정답
- **④** 크롤링: 웹 페이지를 **직접 방문·탐색**하며 긁어오는 수집 방식. "방문하지 않고도"와 반대.

**출제 포인트:** Open API=호출, RSS=구독(XML 배급), FTP=파일 전송, 크롤링=방문 수집. "XML 배급·구독" 키워드는 RSS로 즉시 연결.

**근거:** RSS(Rich Site Summary)는 웹 사이트의 갱신 콘텐츠를 XML 기반 표준 형식으로 배급하여 구독자가 자동으로 수집할 수 있게 하는 기술이다.
</details>

### Q1-044 [난이도: 하] [태그: 1과목/데이터수집및저장계획/로그수집기]

수집 대상 서버에 설치된 에이전트(agent)가 로그를 수집하고 컬렉터(collector)가 이를 모아 HDFS에 저장하는, 하둡의 서브프로젝트로 개발된 로그 수집 기술은?

① 플룸(Flume)
② 카프카(Kafka)
③ 로그스태시(Logstash)
④ 척와(Chukwa)

<details><summary>정답 및 해설</summary>

**정답: ④**

- **①** 플룸: 이벤트·에이전트 기반 로그 수집기이지만 내부 구조가 **소스(source)–채널(channel)–싱크(sink)** 로 구성. 하둡 서브프로젝트로 출발한 에이전트–컬렉터 구조가 아님.
- **②** 카프카: 발행-구독(pub-sub) 모델의 분산 **메시징 시스템**. 로그 수집기 자체가 아님.
- **③** 로그스태시: 엘라스틱 스택(Elastic Stack)의 수집 파이프라인. 구조는 **입력(input)–필터(filter)–출력(output)**.
- **④** 척와: **에이전트(수집)–컬렉터(저장)** 구조로 분산 시스템의 로그를 모아 **HDFS에 저장**하는 하둡 서브프로젝트. ← 정답

**출제 포인트:** 로그 수집기 구조 매칭 — 척와: 에이전트–컬렉터·HDFS 저장 / 플룸: 소스–채널–싱크 / 로그스태시: 입력–필터–출력. "하둡 서브프로젝트 + 컬렉터"가 보이면 척와.

**근거:** 척와(Chukwa)는 에이전트가 수집한 로그 데이터를 컬렉터가 받아 HDFS에 저장하는, 하둡 기반 분산 시스템 모니터링·로그 수집 기술이다.
</details>

### Q1-045 [난이도: 중] [태그: 1과목/데이터수집및저장계획/ETL·ELT차이]

ETL과 ELT에 대한 설명으로 옳지 <u>않은</u> 것은?

① ETL은 원천 데이터를 변환한 후 목표 시스템에 적재한다.
② ELT는 적재하기 전에 반드시 모든 변환을 완료해야 한다.
③ ELT는 원본 데이터를 먼저 적재한 뒤 필요할 때 목적지 시스템의 처리 능력으로 변환하며, 데이터 레이크(data lake) 환경에 적합하다.
④ ETL은 전통적으로 데이터 웨어하우스(DW) 구축에 주로 사용되어 왔다.

<details><summary>정답 및 해설</summary>

**정답: ②**

- **①** 옳은 설명. 변환(T)이 적재(L)보다 먼저인 것이 ETL의 정의.
- **②** ELT는 **변환 전에 원본을 먼저 적재**하는 방식이다. "적재 전에 변환 완료"는 ETL의 특징을 뒤집어 놓은 틀린 설명. ← 정답
- **③** 옳은 설명. 원본 보존 + 목적지에서 변환 = ELT, 데이터 레이크와 궁합.
- **④** 옳은 설명. 정해진 스키마로 변환해 적재하는 ETL은 DW의 전통적 방식.

**출제 포인트:** 변환 위치로 구분 — ETL은 **적재 전(중간 단계)** 변환·DW용, ELT는 **적재 후(목적지)** 변환·데이터 레이크용. 부정형에서 두 방식의 특징을 서로 바꿔 출제하는 것이 단골.

**근거:** ELT는 원천 데이터를 변환 없이 먼저 적재(Load)한 후 목적지 시스템에서 필요 시점에 변환(Transform)하는 방식이다.
</details>

### Q1-046 [난이도: 중] [태그: 1과목/데이터수집및저장계획/수집기술매칭]

데이터 유형과 수집 기술의 연결로 옳지 <u>않은</u> 것은?

① 정형 데이터 — ETL, 스쿱(Sqoop)
② 반정형 데이터 — 플룸(Flume), 스크라이브(Scribe)
③ 비정형 데이터 — 크롤링(crawling), 스크래파이(Scrapy)
④ 정형 데이터 — 척와(Chukwa), 크롤링(crawling)

<details><summary>정답 및 해설</summary>

**정답: ④**

- **①** 옳은 연결. 스키마가 고정된 정형 데이터는 ETL·스쿱으로 수집.
- **②** 옳은 연결. 로그(반정형)는 플룸·스크라이브 같은 로그 수집기로 수집.
- **③** 옳은 연결. 웹 문서·텍스트 등 비정형은 크롤링·스크래파이로 수집.
- **④** 척와는 **반정형(로그)** 수집 기술, 크롤링은 **비정형** 수집 기술이다. 정형과의 연결은 틀림. ← 정답

**출제 포인트:** 유형별 3줄 암기 — 정형: ETL·Sqoop / 반정형: Flume·Scribe·Chukwa(로그 수집기 계열) / 비정형: 크롤링·Scrapy. 함정은 항상 기술을 다른 유형 칸에 옮겨 놓는 방식으로 나온다.

**근거:** 데이터 수집 기술은 데이터 유형에 따라 정형(ETL·Sqoop), 반정형(Flume·Scribe·Chukwa 등 로그 수집기), 비정형(크롤링·Scrapy 등)으로 구분하여 적용한다.
</details>

### Q1-047 [난이도: 중] [태그: 1과목/데이터수집및저장계획/로그수집기]

이벤트(event)와 에이전트(agent)를 기반으로 하며, 소스(source)–채널(channel)–싱크(sink) 구조로 대용량 로그 데이터를 안정적으로 수집하는 기술은?

① 플룸(Flume)
② 로그스태시(Logstash)
③ 스크라이브(Scribe)
④ 스쿱(Sqoop)

<details><summary>정답 및 해설</summary>

**정답: ①**

- **①** 플룸: **이벤트·에이전트 기반**, 에이전트 내부가 **소스–채널–싱크** 3요소로 구성. ← 정답
- **②** 로그스태시: 엘라스틱 스택(Elastic Stack)의 수집 파이프라인. 구조는 **입력(input)–필터(filter)–출력(output)**.
- **③** 스크라이브: 페이스북이 개발한 실시간 스트리밍 로그 수집기. 소스–채널–싱크 구조가 아님.
- **④** 스쿱: RDB↔하둡 간 **정형 데이터** 전송 도구. 로그 수집기가 아님.

**출제 포인트:** 로그 수집기 식별 키워드 — 플룸: 이벤트·에이전트·소스/채널/싱크 / 플루언티드(Fluentd): 태그 기반 라우팅·JSON 통합 / 스크라이브: 페이스북·실시간 스트리밍 / 로그스태시: 엘라스틱 스택·입력/필터/출력.

**근거:** 플룸(Flume)은 이벤트와 에이전트를 기반으로 소스·채널·싱크로 구성된 에이전트를 통해 대용량 로그 데이터를 수집·전송하는 기술이다.
</details>

### Q1-048 [난이도: 중] [태그: 1과목/데이터수집및저장계획/데이터품질기준]

데이터 품질 기준에 대한 설명으로 옳지 <u>않은</u> 것은?

① 정확성(accuracy): 데이터가 실세계의 사실·값을 올바르게 반영하는 정도
② 완전성(completeness): 필요한 데이터가 누락 없이 모두 존재하는 정도
③ 적시성(timeliness): 데이터의 표현 형식·단위·값 체계가 서로 모순되지 않는 정도
④ 일관성(consistency): 여러 시스템·항목에 저장된 동일 데이터가 서로 다르지 않고 일치하는 정도

<details><summary>정답 및 해설</summary>

**정답: ③**

- **①** 옳은 설명. 정확성 = 실제 값과의 부합.
- **②** 옳은 설명. 완전성 = 누락 없음.
- **③** "형식·단위·값 체계의 무모순"은 **일관성**의 정의다. 적시성은 **필요한 시점에 최신 상태의 데이터가 제공되는 정도**를 의미한다. ← 정답
- **④** 옳은 설명. 일관성 = 시스템·항목 간 무모순·일치.

**출제 포인트:** 품질 4대 기준 한 줄 암기 — 정확성=맞는 값, 완전성=빠짐 없음, 적시성=제때 최신, 일관성=서로 모순 없음. 부정형은 적시성↔일관성 정의 바꿔치기가 단골. ※ 교재별 표기 차이 있음 — 품질 기준 목록에 유효성·접근성 등을 추가하는 교재도 있다.

**근거:** 적시성(timeliness)은 데이터가 필요한 시점에 최신 상태로 제공되어 활용 가능한 정도를 나타내는 데이터 품질 기준이다.
</details>

### Q1-049 [난이도: 중] [태그: 1과목/데이터수집및저장계획/데이터변환기법]

데이터 변환 기법에 대한 설명으로 옳지 <u>않은</u> 것은?

① 집계(aggregation)는 데이터를 요약·합산하여 규모를 축소하는 기법이다.
② 일반화(generalization)는 기존 속성을 조합해 새로운 속성을 추가함으로써 데이터의 차원을 늘리는 기법이다.
③ 정규화(normalization)는 데이터 값을 정해진 구간(예: 0~1)에 들어가도록 척도를 변환하는 기법이다.
④ 속성 생성(attribute construction)은 기존 속성들로부터 분석에 유용한 새로운 속성을 만들어내는 기법이다.

<details><summary>정답 및 해설</summary>

**정답: ②**

- **①** 옳은 설명. 일별 매출 → 월별 합계처럼 요약하는 것이 집계.
- **②** "새 속성 추가"는 **속성 생성**의 정의다. 일반화는 **낮은 수준의 값을 상위 개념(범주·구간)으로 대체**하는 기법(예: 나이 → 연령대). ← 정답
- **③** 옳은 설명. 최소-최대 정규화, Z-점수(z-score) 정규화 등이 해당.
- **④** 옳은 설명. 예: 키·몸무게로 BMI 속성을 새로 만드는 것.

**출제 포인트:** 부정형의 단골 수법 = 일반화와 속성 생성의 정의 바꿔치기. 일반화는 "위로 뭉뚱그리기", 속성 생성은 "새로 만들기"로 구분. ※ 교재별 표기 차이 있음 — 일반화를 '특정 구간에 분포하도록 값의 스케일을 변화시키는 기법'으로 서술하는 교재도 있다.

**근거:** 일반화(generalization)는 세부적인 하위 수준의 데이터 값을 연령대·지역 등 상위 개념의 값으로 대체하는 데이터 변환 기법이다.
</details>

### Q1-050 [난이도: 중] [태그: 1과목/데이터수집및저장계획/OpenAPI·RSS·FTP]

파일 전송 프로토콜 FTP(File Transfer Protocol)에 대한 설명으로 옳은 것은?

① UDP 기반 프로토콜이므로 전송의 신뢰성을 보장하지 않는다.
② 능동(active) 모드에서는 클라이언트가 서버의 데이터 포트에 먼저 접속하여 데이터 연결을 생성한다.
③ 수동(passive) 모드에서는 서버가 알려 준 임의의 포트로 클라이언트가 접속하여 데이터 연결을 생성한다.
④ 제어(명령) 연결에는 기본적으로 20번 포트가 사용된다.

<details><summary>정답 및 해설</summary>

**정답: ③**

- **①** FTP는 **TCP/IP 기반** 프로토콜로 연결 지향적이며 전송 신뢰성을 보장한다. UDP 기반이라는 설명은 틀림.
- **②** 능동 모드에서는 **서버가** 클라이언트가 알려 준 포트로 **먼저 접속**하여 데이터 연결을 만든다. 클라이언트가 서버에 접속한다는 설명은 수동 모드와 뒤바뀐 것.
- **③** 옳은 설명. 수동 모드 = 서버가 데이터 연결용 임의 포트를 알려 주고 **클라이언트가 그 포트로 접속**. ← 정답
- **④** 제어(명령) 연결의 기본 포트는 **21번**이다. 20번은 **능동 모드의 데이터 연결**에 사용되는 포트.

**출제 포인트:** FTP 모드는 "데이터 연결을 누가 시작하는가"로 구분 — 능동: 서버→클라이언트, 수동: 클라이언트→서버. 포트는 제어 21번 / 능동 모드 데이터 20번 짝으로 암기.

**근거:** FTP는 TCP/IP 기반 파일 전송 프로토콜로 제어 연결(21번 포트)과 데이터 연결을 분리하며, 능동 모드는 서버가, 수동 모드는 클라이언트가 데이터 연결을 시작한다.
</details>

### Q1-051 [난이도: 상] [태그: 1과목/데이터수집및저장계획/수집기술·품질종합]

데이터 수집 기술과 품질 기준에 대한 설명 중 옳은 것만 모두 고른 것은?

- ㄱ. FTP는 TCP/IP 기반의 파일 전송 프로토콜로, 대용량 파일 수집에 활용된다.
- ㄴ. Open API는 배포자가 갱신 콘텐츠를 XML 형식으로 밀어 보내면 구독자가 자동 수신하는 방식이다.
- ㄷ. 완전성(completeness)은 필요한 데이터가 누락 없이 존재하는 정도를 의미한다.
- ㄹ. 일관성(consistency)은 데이터가 서로 모순 없이 동일한 형식·값 체계를 유지하는 정도를 의미한다.

① ㄱ, ㄷ, ㄹ  ② ㄱ, ㄴ, ㄷ  ③ ㄴ, ㄷ, ㄹ  ④ ㄱ, ㄴ, ㄹ

<details><summary>정답 및 해설</summary>

**정답: ①**

- **ㄱ (O)** FTP = TCP/IP 기반 파일 전송 프로토콜, 대용량 파일 송수신에 사용.
- **ㄴ (X)** XML 배급·구독 방식은 **RSS**의 설명이다. Open API는 이용자가 공개된 인터페이스를 **호출(요청)**하여 데이터를 받는 방식.
- **ㄷ (O)** 완전성 = 누락 없음.
- **ㄹ (O)** 일관성 = 형식·값 체계의 무모순.

따라서 옳은 것은 ㄱ, ㄷ, ㄹ → **①**. (②·④는 틀린 ㄴ을 포함, ③은 옳은 ㄱ을 누락하고 ㄴ을 포함)

**출제 포인트:** Open API와 RSS의 구분은 "누가 움직이는가" — Open API는 수집자가 호출(pull), RSS는 갱신 콘텐츠의 배급을 구독. 품질 기준은 정확성·완전성·적시성·일관성 4개를 정의와 1:1로 묶어 암기.

**근거:** Open API는 서비스 제공자가 공개한 프로그래밍 인터페이스를 호출하여 실시간으로 데이터를 수집하는 방식이고, FTP는 TCP/IP 기반으로 서버-클라이언트 간 파일을 송수신하는 프로토콜이다.
</details>

### Q1-052 [난이도: 상] [태그: 1과목/데이터수집및저장계획/데이터변환기법]

어느 기업이 고객 데이터를 다음과 같이 전환했다.

- (가) 고객 나이 값 23, 35, 47을 각각 '20대', '30대', '40대'로 대체했다.
- (나) 일별 매출 데이터를 합산하여 월별 매출 데이터로 만들었다.

(가)와 (나)에 적용된 데이터 변환 기법을 순서대로 바르게 짝지은 것은?

① 평활화 — 집계
② 일반화 — 정규화
③ 평활화 — 속성 생성
④ 일반화 — 집계

<details><summary>정답 및 해설</summary>

**정답: ④**

- **(가)** 세부 값(나이)을 상위 개념(연령대)으로 대체 → **일반화**. 구간을 나눈다는 점 때문에 평활화(구간화)로 착각하기 쉬우나, 평활화의 목적은 **노이즈 제거**이고 여기서는 상위 개념화가 목적이다.
- **(나)** 일별 데이터를 합산해 요약 → **집계**.
- **①** (가)를 평활화로 본 함정. 목적이 노이즈 제거가 아니므로 틀림.
- **②** (나)는 척도 변환이 아니라 요약·합산이므로 정규화가 아님.
- **③** (가)는 평활화가 아니고, (나)는 새 속성을 만든 것이 아니라 요약한 것.
- **④** 일반화 — 집계. ← 정답

**출제 포인트:** 사례형 판별 기준은 "목적" — 노이즈 제거면 평활화, 상위 개념 대체면 일반화, 요약·합산이면 집계, 척도 변환이면 정규화, 새 속성이면 속성 생성. 나이→연령대는 일반화의 대표 예시.

**근거:** 데이터 전환에서 일반화는 하위 수준 값을 상위 개념으로 대체하는 기법이고, 집계는 데이터를 합산·요약하여 축약된 형태로 만드는 기법이다.
</details>
