### Q1-053 [난이도: 하] [태그: 1과목/데이터수집및저장계획/NoSQL유형]

문서 기반(Document Store) NoSQL 데이터베이스의 대표 제품은?

① Redis  ② MongoDB  ③ Neo4j  ④ HBase

<details><summary>정답 및 해설</summary>

**정답: ②**

- **①** Redis: 키-값(Key-Value) 저장소. 인메모리 기반의 단순 키-값 구조.
- **②** MongoDB: JSON 유사 문서(BSON) 단위로 저장하는 문서 기반(Document Store) 저장소. ← 정답
- **③** Neo4j: 노드·엣지로 관계를 표현하는 그래프(Graph) 저장소.
- **④** HBase: 컬럼 패밀리 단위로 저장하는 컬럼 기반(Column-family) 저장소.

**출제 포인트:** NoSQL 4유형-제품 매칭 = **Key-Value: Redis / Document: MongoDB / Column: HBase·Cassandra / Graph: Neo4j**. "몽고는 문서, 레디스는 키-값, 네오는 그래프, 나머지(HBase·Cassandra)는 컬럼"으로 암기.

**근거:** 문서 기반 NoSQL은 JSON·XML 등 문서 단위로 데이터를 저장·조회하는 유형으로, MongoDB가 대표 제품이다.
</details>

### Q1-054 [난이도: 하] [태그: 1과목/데이터수집및저장계획/데이터웨어하우스]

데이터 웨어하우스(Data Warehouse)의 4가지 특징에 해당하지 <u>않는</u> 것은?

① 주제 지향성(subject-oriented)
② 통합성(integrated)
③ 시계열성(time-variant)
④ 휘발성(volatile)

<details><summary>정답 및 해설</summary>

**정답: ④**

- **①** 주제 지향성: 업무 기능이 아니라 고객·상품 등 분석 **주제 중심**으로 데이터를 구성 → 특징에 포함.
- **②** 통합성: 여러 운영 시스템의 데이터를 **일관된 형식·코드로 통합** 저장 → 특징에 포함.
- **③** 시계열성: **시점 정보를 함께 보관**하여 과거 이력 분석이 가능 → 특징에 포함.
- **④** DW는 휘발성이 아니라 **비휘발성(non-volatile)** — 일단 적재된 데이터는 일괄 적재 외에 수시 갱신·삭제되지 않는다. ← 정답

**출제 포인트:** DW 특징 4 = **주제 지향·통합·시계열·비휘발**("주통시비"). 부정형에서 "휘발성", "실시간 갱신"으로 바꿔치기하는 선지가 단골.

**근거:** 데이터 웨어하우스는 의사결정 지원을 위해 주제 지향적·통합적·시계열적·비휘발적으로 구축되는 데이터 저장소다.
</details>

### Q1-055 [난이도: 중] [태그: 1과목/데이터수집및저장계획/CAP정리]

분산 데이터 저장 시스템에 관한 CAP 정리(CAP theorem)의 설명으로 옳은 것은?

① 일관성(Consistency)은 모든 노드가 언제든 요청에 응답할 수 있는 성질이다.
② 분산 데이터베이스는 세 가지 속성을 모두 동시에 보장하도록 설계된다.
③ 네트워크 분할이 발생한 상황에서는 일관성과 가용성 중 하나를 선택해야 한다.
④ 가용성(Availability)은 모든 노드가 같은 시점에 동일한 데이터를 보는 성질이다.

<details><summary>정답 및 해설</summary>

**정답: ③**

- **①** 언제든 응답 가능한 성질은 **가용성(Availability)**. 일관성의 정의와 바꿔치기한 선지.
- **②** CAP 정리의 핵심이 바로 "**세 속성을 동시에 모두 만족할 수 없다**"이다. 정면으로 어긋나는 설명.
- **③** 분산 환경에서 분할 허용성(Partition tolerance)은 사실상 포기할 수 없으므로, 분할 발생 시 **일관성(CP)과 가용성(AP) 중 택일**해야 한다. ← 정답
- **④** 모든 노드가 동일 데이터를 보는 성질은 **일관성(Consistency)**. 가용성의 정의와 바꿔치기한 선지.

**출제 포인트:** CAP = **C**onsistency(모든 노드 동일 데이터) · **A**vailability(항상 응답) · **P**artition tolerance(분할에도 동작). **최대 2개만 보장** — 분산 시스템은 P가 전제이므로 실질 선택지는 CP vs AP.

**근거:** CAP 정리는 분산 시스템이 일관성·가용성·분할 허용성 세 속성 중 최대 두 가지만 동시에 보장할 수 있다는 원리다.
</details>

### Q1-056 [난이도: 중] [태그: 1과목/데이터수집및저장계획/ACID·BASE]

트랜잭션 속성 ACID와 BASE에 대한 설명으로 옳은 것은?

① BASE는 기본적 가용성(Basically Available), 소프트 상태(Soft state), 최종 일관성(Eventually consistent)을 의미하며 NoSQL이 주로 채택하는 느슨한 일관성 모델이다.
② ACID는 NoSQL의 특성이고, BASE는 관계형 데이터베이스의 트랜잭션 특성이다.
③ BASE 모델은 모든 시점에 강한 일관성(strong consistency)을 보장한다.
④ ACID의 D(Durability)는 트랜잭션을 언제든지 취소할 수 있음을 의미한다.

<details><summary>정답 및 해설</summary>

**정답: ①**

- **①** BASE = **B**asically **A**vailable(기본적 가용성) + **S**oft state(소프트 상태) + **E**ventually consistent(최종 일관성). 일관성을 일부 늦추는 대신 가용성을 우선하는 NoSQL의 모델. ← 정답
- **②** 반대로 서술한 선지. **ACID는 RDBMS**의 트랜잭션 특성, **BASE는 NoSQL**의 특성.
- **③** BASE는 강한 일관성이 아니라 **최종 일관성**(시간이 지나면 결국 일치)을 허용한다.
- **④** D(Durability, 지속성)는 **완료(commit)된 트랜잭션의 결과가 영구 보존**됨을 의미. 취소 가능성과 무관.

**출제 포인트:** ACID = 원자성(Atomicity)·일관성(Consistency)·독립성(Isolation)·지속성(Durability) → RDBMS·강한 일관성. BASE = 기본적 가용성·소프트 상태·최종 일관성 → NoSQL·가용성 우선. "ACID는 은행(정확), BASE는 SNS(빠름)"로 암기.

**근거:** BASE는 강한 일관성 대신 기본적 가용성·소프트 상태·최종 일관성을 채택하여 가용성과 확장성을 우선하는 NoSQL의 트랜잭션 모델이다.
</details>

### Q1-057 [난이도: 중] [태그: 1과목/데이터수집및저장계획/HDFS]

하둡 분산 파일 시스템(HDFS)에 대한 설명으로 옳지 <u>않은</u> 것은?

① 네임노드(NameNode)는 파일 시스템의 메타데이터를 관리한다.
② 데이터노드(DataNode)가 메타데이터를 저장하고, 네임노드가 실제 데이터 블록을 저장한다.
③ 파일은 블록(block) 단위로 분할되어 여러 데이터노드에 분산 저장된다.
④ 블록은 기본적으로 여러 노드에 복제 저장되어 일부 노드 장애 시에도 데이터를 보존할 수 있다.

<details><summary>정답 및 해설</summary>

**정답: ②**

- **①** 옳은 설명. 네임노드는 파일명·디렉터리 구조·블록 위치 등 **메타데이터**를 관리하는 마스터 노드.
- **②** 역할을 뒤바꾼 선지. **네임노드=메타데이터, 데이터노드=실제 블록 저장**이 올바른 구조다. ← 정답
- **③** 옳은 설명. 대용량 파일을 블록으로 쪼개 여러 데이터노드에 분산 저장한다.
- **④** 옳은 설명. 블록 복제(기본 복제 계수 3)로 장애 허용(fault tolerance)을 확보한다.

**출제 포인트:** HDFS = 마스터(네임노드: 메타데이터) + 슬레이브(데이터노드: 실제 블록). 블록 복제 계수 기본 3. 블록 크기 기본 128MB ※ 교재별 표기 차이 있음(하둡 2.x 이상 기본 128MB, 1.x는 64MB).

**근거:** HDFS는 네임노드가 메타데이터를, 데이터노드가 실제 데이터 블록을 담당하며 블록 복제를 통해 장애 허용성을 확보하는 분산 파일 시스템이다.
</details>

### Q1-058 [난이도: 중] [태그: 1과목/데이터수집및저장계획/데이터마트]

어느 기업이 전사 데이터 웨어하우스에서 마케팅 부서가 필요로 하는 데이터만 추출하여, 마케팅 분석 전용의 소규모 주제 지향적 저장소를 구축하려 한다. 이에 해당하는 것은?

① 데이터 마트(Data Mart)
② 데이터 레이크(Data Lake)
③ ODS(Operational Data Store)
④ 데이터 웨어하우스(Data Warehouse)

<details><summary>정답 및 해설</summary>

**정답: ①**

- **①** 데이터 마트: DW의 일부를 **특정 부서·주제** 단위로 추출한 소규모 저장소. "마케팅 전용·소규모"에 부합. ← 정답
- **②** 데이터 레이크: 정형·비정형 **원시(raw) 데이터를 가공 없이** 대규모로 축적하는 저장소. 부서 전용 추출과 무관.
- **③** ODS: DW 적재 전 **운영계 데이터를 임시 통합**하는 중간 저장소. 분석 전용 저장소가 아님.
- **④** 데이터 웨어하우스: **전사** 차원의 통합 저장소. 문제의 "전사 DW에서 추출"한 결과물이 아니라 원천에 해당.

**출제 포인트:** 규모·목적으로 구분 — **ODS(운영계 임시 통합) → DW(전사 통합) → 마트(부서·주제별 부분집합)**, 레이크는 별도로 "원시 데이터 그대로" 축적. "마트는 DW의 부분집합"이 핵심.

**근거:** 데이터 마트는 데이터 웨어하우스의 데이터 중 특정 부서나 주제 영역에 필요한 부분만 추출하여 구축한 소규모 주제 지향적 저장소다.
</details>

### Q1-059 [난이도: 상] [태그: 1과목/데이터수집및저장계획/데이터레이크]

데이터 저장소에 대한 설명으로 옳지 <u>않은</u> 것은?

① 데이터 레이크는 원시(raw) 데이터를 원래 형식 그대로 저장하며, 스키마를 읽는 시점에 적용한다(Schema-on-Read).
② ODS는 데이터 웨어하우스 적재 전에 운영계 데이터를 임시로 통합·저장하는 저장소다.
③ 데이터 마트는 정형·비정형 원시 데이터를 가공 없이 그대로 축적한다는 점에서 데이터 레이크와 성격이 같다.
④ 데이터 웨어하우스는 정제·통합된 정형 데이터를 적재 시점에 스키마에 맞춰 저장한다(Schema-on-Write).

<details><summary>정답 및 해설</summary>

**정답: ③**

- **①** 옳은 설명. 레이크는 가공 전 원시 데이터를 그대로 두고, **분석(읽기) 시점에 구조를 부여**한다.
- **②** 옳은 설명. ODS는 운영계와 DW 사이의 **중간 임시 통합** 저장소.
- **③** 데이터 마트는 **정제·요약된 정형 데이터를 특정 주제별로** 담는 저장소로, 원시 데이터를 무가공 축적하는 레이크와 정반대 성격이다. 레이크의 특징을 마트에 뒤집어씌운 함정. ← 정답
- **④** 옳은 설명. DW는 **적재 시점에 정해진 스키마**로 정제·변환 후 저장한다.

**출제 포인트:** 함정 구분 — **마트/DW = 정제된 정형 + Schema-on-Write**, **레이크 = 원시 데이터(정형·비정형) + Schema-on-Read**. "레이크는 날것, 마트는 완제품"으로 암기.

**근거:** 데이터 레이크는 정형·비정형 원시 데이터를 가공하지 않고 원래 형식 그대로 저장했다가 활용 시점에 스키마를 적용하는 대규모 저장소다.
</details>

### Q1-060 [난이도: 상] [태그: 1과목/데이터수집및저장계획/NoSQL유형]

NoSQL 데이터베이스에 대한 설명 중 옳은 것만 모두 고른 것은?

- ㄱ. Redis는 키-값(Key-Value) 기반 저장소다.
- ㄴ. 컬럼 기반(Column-family) 저장소는 데이터를 행(row) 단위로만 저장하므로 특정 컬럼에 대한 조회·집계 분석에 불리하다.
- ㄷ. HBase와 Cassandra는 컬럼 기반(Column-family) 저장소다.
- ㄹ. NoSQL은 일반적으로 BASE 속성을 따르며 최종 일관성(eventual consistency)을 허용한다.

① ㄱ, ㄴ  ② ㄴ, ㄷ, ㄹ  ③ ㄱ, ㄴ, ㄷ  ④ ㄱ, ㄷ, ㄹ

<details><summary>정답 및 해설</summary>

**정답: ④**

- **ㄱ (O)** Redis는 인메모리 기반의 키-값(Key-Value) 저장소다.
- **ㄴ (X)** 컬럼 기반 저장소는 행이 아니라 **컬럼(패밀리) 단위로 저장**하므로, 특정 컬럼만 읽어 조회·집계하는 분석에 오히려 **유리**하다. 특징을 정반대로 뒤집은 서술.
- **ㄷ (O)** HBase·Cassandra는 컬럼 패밀리 단위로 저장하는 컬럼 기반 저장소다.
- **ㄹ (O)** NoSQL은 ACID 대신 BASE를 채택하여 가용성을 우선하고 최종 일관성을 허용하는 것이 일반적이다.

따라서 옳은 것은 ㄱ, ㄷ, ㄹ → **④**. (①·③은 틀린 ㄴ을 포함하거나 옳은 ㄹ을 누락, ②는 틀린 ㄴ을 포함)

**출제 포인트:** 제품-유형 매칭(**Redis=키-값 / MongoDB=문서 / HBase·Cassandra=컬럼 / Neo4j=그래프**)에 유형별 특징·트랜잭션 모델까지 조합형으로 얹는 문제 — 컬럼 저장소는 **컬럼 단위 저장 → 컬럼 조회·집계에 유리**, NoSQL의 트랜잭션 모델은 **BASE(최종 일관성)**.

**근거:** NoSQL은 키-값·문서·컬럼·그래프의 4가지 유형으로 분류되고, 컬럼 기반 저장소는 컬럼 단위 저장으로 컬럼 조회·집계에 유리하며, NoSQL은 일반적으로 BASE 속성에 기반한 최종 일관성 모델을 채택한다.
</details>
