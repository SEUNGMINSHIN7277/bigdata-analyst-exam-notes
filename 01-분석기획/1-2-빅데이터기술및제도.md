### Q1-011 [난이도: 하] [태그: 1과목/빅데이터의이해/하둡에코시스템]

대용량 파일을 블록(block) 단위로 나누어 여러 노드에 분산 저장하고, 블록의 복제본(replica)을 두어 노드 장애에 대비하는 하둡(Hadoop)의 분산 파일 저장 컴포넌트는?

① HDFS  ② MapReduce  ③ YARN  ④ HBase

<details><summary>정답 및 해설</summary>

**정답: ①**

- **①** HDFS(Hadoop Distributed File System): 블록 단위 분산 저장 + 복제를 통한 장애 허용(fault tolerance). ← 정답
- **②** MapReduce: 저장이 아니라 분산 **처리**(Map→Reduce 연산) 프레임워크.
- **③** YARN: 클러스터의 **자원 관리·작업 스케줄링** 담당. 저장 기능 아님.
- **④** HBase: HDFS 위에서 동작하는 컬럼 기반 NoSQL **데이터베이스**. 파일 시스템 자체가 아님.

**출제 포인트:** 하둡 핵심 3요소 = HDFS(저장) / MapReduce(처리) / YARN(자원 관리). "블록·복제·분산 저장"이 보이면 HDFS.

**근거:** HDFS는 대용량 파일을 블록 단위로 분할해 여러 노드에 분산 저장하고 복제본을 유지하여 장애에 대비하는 하둡의 분산 파일 시스템이다.
</details>

### Q1-012 [난이도: 하] [태그: 1과목/빅데이터의이해/하둡에코시스템]

분산 환경에서 여러 서버가 공유하는 설정 정보의 유지·관리, 서버 간 동기화, 리더 선출(leader election) 등 분산 애플리케이션의 코디네이션(coordination)을 담당하는 하둡 에코시스템 컴포넌트는?

① Oozie  ② Zookeeper  ③ Avro  ④ Hive

<details><summary>정답 및 해설</summary>

**정답: ②**

- **①** Oozie(우지): 하둡 작업(MapReduce·Pig 등)의 **워크플로(workflow)를 정의·스케줄링**하는 관리 도구. 코디네이션 서비스가 아님.
- **②** Zookeeper(주키퍼): 분산 환경의 **설정 관리·동기화·네이밍·리더 선출**을 담당하는 분산 코디네이션 서비스. ← 정답
- **③** Avro(에이브로): 데이터 구조를 정의해 저장·교환하는 **데이터 직렬화(serialization)** 시스템.
- **④** Hive(하이브): SQL 유사 언어(HiveQL)로 하둡 데이터를 **질의·분석**하는 도구.

**출제 포인트:** 관리·운영 계열 컴포넌트 구분 — Zookeeper=분산 코디네이션(설정·동기화·리더 선출), Oozie=워크플로 스케줄링, Avro=직렬화. "동물원 사육사(Zookeeper)가 분산된 동물들을 조율한다"로 암기.

**근거:** 주키퍼(Zookeeper)는 분산 환경에서 설정 정보 관리, 동기화, 리더 선출 등의 기능을 제공하여 분산 애플리케이션의 코디네이션을 지원하는 하둡 에코시스템의 서비스다.
</details>

### Q1-013 [난이도: 중] [태그: 1과목/빅데이터의이해/하둡에코시스템]

하둡 에코시스템 컴포넌트의 역할에 대한 설명으로 옳지 <u>않은</u> 것은?

① Hive는 SQL과 유사한 HiveQL로 하둡에 저장된 데이터를 질의·분석한다.
② Flume은 여러 서버에서 발생하는 대량의 로그 데이터를 수집하여 저장소로 전송한다.
③ Kafka는 발행-구독(publish-subscribe) 모델 기반의 분산 메시징 시스템으로 대용량 실시간 데이터 스트림을 처리한다.
④ Pig는 관계형 데이터베이스와 하둡 간의 대량 데이터 전송을 담당한다.

<details><summary>정답 및 해설</summary>

**정답: ④**

- **①** 옳은 설명. Hive = 데이터 웨어하우스 도구, HiveQL로 SQL식 질의.
- **②** 옳은 설명. Flume = 로그 수집·집계·이동.
- **③** 옳은 설명. Kafka = pub-sub 분산 메시지 큐, 실시간 스트림 처리 기반.
- **④** RDB ↔ 하둡 전송은 **Sqoop**의 역할. Pig는 절차형 스크립트 언어 **Pig Latin**으로 데이터 흐름(변환·처리)을 기술하는 도구. ← 정답

**출제 포인트:** Pig와 Sqoop 바꿔치기가 단골 함정. Pig=Pig Latin 스크립트 처리, Sqoop=RDB 전송, Hive=SQL식 질의. "돼지(Pig)는 라틴어(Pig Latin)를 쓴다"로 암기.

**근거:** 피그(Pig)는 절차형 스크립트 언어인 Pig Latin을 사용해 대용량 데이터의 변환·처리 흐름을 기술하는 하둡 기반 데이터 처리 도구이다.
</details>

### Q1-014 [난이도: 중] [태그: 1과목/빅데이터의이해/하둡에코시스템]

디스크 입출력 중심의 MapReduce와 달리 인메모리(in-memory) 기반 연산을 수행하여 반복 연산·머신러닝 작업에서 빠른 처리 속도를 보이는 분산 데이터 처리 엔진은?

① MapReduce  ② HBase  ③ Spark  ④ YARN

<details><summary>정답 및 해설</summary>

**정답: ③**

- **①** MapReduce: 중간 결과를 **디스크에 기록**하며 처리. 반복 연산에 상대적으로 느림 → 문제의 비교 대상.
- **②** HBase: 컬럼 기반 NoSQL 데이터베이스. 처리 엔진이 아니라 저장소.
- **③** Spark: **메모리 상에서** 데이터를 유지하며 연산 → 반복 연산·머신러닝·실시간 처리에 유리. ← 정답
- **④** YARN: 자원 관리·스케줄링 컴포넌트. 데이터 처리 엔진 아님.

**출제 포인트:** "인메모리", "반복 연산", "MapReduce보다 빠름" 키워드 → Spark. 처리 방식 비교: MapReduce=디스크 기반 배치, Spark=메모리 기반(배치+스트림+ML).

**근거:** 스파크(Spark)는 인메모리 기반의 분산 데이터 처리 엔진으로, 디스크 기반 MapReduce에 비해 반복 연산과 대화형 분석에서 빠른 성능을 제공한다.
</details>

### Q1-015 [난이도: 상] [태그: 1과목/빅데이터의이해/하둡에코시스템]

하둡 에코시스템에 대한 설명 중 옳은 것만 모두 고른 것은?

- ㄱ. YARN은 하둡 클러스터의 자원 관리와 작업 스케줄링을 담당한다.
- ㄴ. HBase는 HDFS 위에서 동작하는 컬럼(column) 기반 분산 NoSQL 데이터베이스다.
- ㄷ. Hive는 절차형 스크립트 언어인 Pig Latin으로 데이터 처리 흐름을 기술한다.
- ㄹ. Flume은 대량의 로그 데이터를 수집·집계하여 저장소로 전송한다.

① ㄱ, ㄴ, ㄹ  ② ㄱ, ㄷ, ㄹ  ③ ㄴ, ㄷ  ④ ㄱ, ㄴ, ㄷ, ㄹ

<details><summary>정답 및 해설</summary>

**정답: ①**

- **ㄱ (O)** YARN(Yet Another Resource Negotiator) = 자원 관리 + 작업 스케줄링.
- **ㄴ (O)** HBase = HDFS 기반 컬럼형 NoSQL DB. 실시간 랜덤 읽기·쓰기 지원.
- **ㄷ (X)** Pig Latin을 쓰는 것은 **Pig**. Hive는 SQL 유사 언어 **HiveQL**을 사용.
- **ㄹ (O)** Flume = 로그 수집·집계·이동 도구.

따라서 옳은 것은 ㄱ, ㄴ, ㄹ → **①**. (②·③은 틀린 ㄷ을 포함, ④도 ㄷ을 포함)

**출제 포인트:** 질의·스크립트 도구 구분 — Hive=HiveQL(SQL식, 선언형), Pig=Pig Latin(스크립트, 절차형). 조합형에서 이 둘을 바꾼 지문이 오답 축으로 반복 등장.

**근거:** 하둡 에코시스템은 저장(HDFS·HBase), 자원 관리(YARN), 처리(MapReduce·Spark), 수집(Flume·Sqoop·Kafka), 질의(Hive·Pig) 등 역할별 컴포넌트의 집합이다.
</details>

### Q1-016 [난이도: 하] [태그: 1과목/빅데이터의이해/클라우드컴퓨팅]

이용자가 별도의 설치 없이 웹 브라우저로 접속하여 전자우편·문서 편집 등의 응용 소프트웨어를 완성된 서비스 형태로 이용하는 클라우드 서비스 모델은?

① IaaS  ② PaaS  ③ SaaS  ④ 온프레미스(on-premise)

<details><summary>정답 및 해설</summary>

**정답: ③**

- **①** IaaS(Infrastructure as a Service): 서버·스토리지·네트워크 등 **인프라 자원**을 제공. 소프트웨어는 이용자가 직접 구성.
- **②** PaaS(Platform as a Service): 애플리케이션 **개발·실행 환경(플랫폼)** 을 제공. 완성된 앱이 아님.
- **③** SaaS(Software as a Service): **응용 소프트웨어 완제품**을 서비스로 제공. 웹 메일·웹 오피스가 대표 사례. ← 정답
- **④** 온프레미스: 클라우드가 아니라 자체 전산실에 직접 구축·운영하는 방식.

**출제 포인트:** 제공 범위로 구분 — IaaS=인프라까지, PaaS=플랫폼까지, SaaS=소프트웨어까지. "완성된 앱을 그냥 쓴다 = SaaS."

**근거:** SaaS는 응용 소프트웨어를 클라우드 사업자가 완성된 서비스 형태로 제공하고 이용자는 네트워크를 통해 접속하여 사용하는 클라우드 서비스 모델이다.
</details>

### Q1-017 [난이도: 중] [태그: 1과목/빅데이터의이해/클라우드컴퓨팅]

클라우드 컴퓨팅 서비스 모델(IaaS/PaaS/SaaS)에 대한 설명으로 옳은 것은?

① IaaS는 응용 소프트웨어까지 완제품 형태로 제공한다.
② PaaS는 애플리케이션 개발·실행 환경을 제공하므로 이용자는 인프라를 직접 관리하지 않고 애플리케이션 개발·배포에 집중할 수 있다.
③ SaaS는 서버·스토리지·네트워크 등 인프라 자원만을 가상화하여 제공한다.
④ IaaS 이용자는 가상 서버의 운영체제(OS)를 직접 선택하거나 관리할 수 없다.

<details><summary>정답 및 해설</summary>

**정답: ②**

- **①** 응용 소프트웨어 완제품 제공은 **SaaS**의 특징. IaaS는 인프라 자원 제공.
- **②** 옳은 설명. PaaS = 개발·실행 플랫폼 제공, 인프라 관리는 사업자 몫. ← 정답
- **③** 인프라 자원만 제공하는 것은 **IaaS**. SaaS는 소프트웨어까지 제공.
- **④** IaaS는 이용자가 **OS부터 직접 설치·관리**하는 모델. 관리할 수 없다는 설명은 반대.

**출제 포인트:** 이용자 관리 범위 — IaaS: OS부터 위는 이용자 / PaaS: 애플리케이션·데이터만 이용자 / SaaS: 전부 사업자. 특징 바꿔치기 선지에 주의.

**근거:** PaaS는 애플리케이션의 개발·실행에 필요한 플랫폼 환경을 서비스로 제공하여 이용자가 인프라 운영 부담 없이 개발에 집중하도록 하는 클라우드 서비스 모델이다.
</details>

### Q1-018 [난이도: 하] [태그: 1과목/빅데이터의이해/데이터3법]

2020년 개정·시행된 이른바 '데이터 3법'에 해당하지 <u>않는</u> 것은?

① 개인정보 보호법
② 정보통신망 이용촉진 및 정보보호 등에 관한 법률(정보통신망법)
③ 신용정보의 이용 및 보호에 관한 법률(신용정보법)
④ 위치정보의 보호 및 이용 등에 관한 법률(위치정보법)

<details><summary>정답 및 해설</summary>

**정답: ④**

- **①** 데이터 3법 포함. 가명정보 개념 도입, 개인정보보호위원회로 감독 일원화.
- **②** 데이터 3법 포함. 온라인 개인정보 보호 규정이 개인정보 보호법으로 이관·정비됨.
- **③** 데이터 3법 포함. 금융 분야 가명정보(가명처리된 신용정보) 활용 근거 마련.
- **④** 위치정보법은 데이터 3법에 **포함되지 않음**. ← 정답

**출제 포인트:** 데이터 3법 = 개인정보 보호법 + 정보통신망법 + 신용정보법. "개·망·신"으로 암기. 위치정보법·전자정부법 등을 끼워 넣는 선지가 단골.

**근거:** 데이터 3법은 개인정보 보호법, 정보통신망법, 신용정보법의 세 법률 개정안을 통칭하며 가명정보 도입과 개인정보 감독체계 일원화를 골자로 한다.
</details>

### Q1-019 [난이도: 중] [태그: 1과목/빅데이터의이해/가명정보익명정보]

개인정보·가명정보·익명정보에 대한 설명으로 옳은 것은?

① 가명정보는 추가 정보 없이도 특정 개인을 쉽게 알아볼 수 있는 정보다.
② 익명정보는 개인정보 보호법의 보호 대상에 포함된다.
③ 가명정보는 추가 정보를 사용하지 않고는 특정 개인을 알아볼 수 없도록 처리한 정보로, 개인정보의 범위에 포함된다.
④ 개인정보는 살아 있는 개인뿐 아니라 사망한 사람에 관한 정보도 포함한다.

<details><summary>정답 및 해설</summary>

**정답: ③**

- **①** 반대 설명. 가명정보는 **추가 정보 없이는 식별 불가**하도록 가명처리한 정보.
- **②** 익명정보는 더 이상 개인을 알아볼 수 없는 정보로, 개인정보 보호법의 **적용 대상이 아님**(자유롭게 활용 가능).
- **③** 옳은 설명. 가명정보는 개인정보의 일종이므로 법의 적용을 받되, 특례에 따라 동의 없는 활용이 일부 허용된다. ← 정답
- **④** 개인정보는 **살아 있는 개인**에 관한 정보. 사망자 정보는 원칙적으로 해당 없음.

**출제 포인트:** 식별 가능성 스펙트럼 — 개인정보(식별 가능) > 가명정보(추가 정보 결합 시 식별 가능, 법 적용 O) > 익명정보(식별 불가능, 법 적용 X). "가명은 법 안, 익명은 법 밖."

**근거:** 가명정보는 개인정보를 가명처리하여 추가 정보의 사용·결합 없이는 특정 개인을 알아볼 수 없게 한 정보로, 개인정보 보호법상 개인정보에 포함된다.
</details>

### Q1-020 [난이도: 중] [태그: 1과목/빅데이터의이해/가명정보특례]

개인정보 보호법상 정보주체의 동의 없이 가명정보를 처리할 수 있는 목적에 해당하지 <u>않는</u> 것은?

① 통계작성
② 과학적 연구
③ 공익적 기록보존
④ 특정 개인을 대상으로 한 맞춤형 광고 발송

<details><summary>정답 및 해설</summary>

**정답: ④**

- **①** 특례 목적에 포함. 시장조사 등 상업적 목적의 통계작성도 포함된다.
- **②** 특례 목적에 포함. 기술 개발·실증 등 산업적 연구도 과학적 연구에 포함된다.
- **③** 특례 목적에 포함. 공익적 가치가 있는 기록의 보존.
- **④** 특정 개인에게 연락·광고하려면 그 개인을 식별해야 하므로 가명정보 특례의 취지에 반함. 특례 목적이 **아님**. ← 정답

**출제 포인트:** 가명정보 특례 3목적 = **통계작성 · 과학적 연구 · 공익적 기록보존**. "통·과·공"으로 암기. 함정 포인트: 상업적 통계·산업적 연구는 포함되지만, 특정 개인 식별·마케팅 접촉은 불가.

**근거:** 개인정보 보호법은 통계작성, 과학적 연구, 공익적 기록보존 등의 목적에 한해 정보주체의 동의 없이 가명정보를 처리할 수 있도록 특례를 두고 있다.
</details>

### Q1-021 [난이도: 중] [태그: 1과목/빅데이터의이해/비식별화기법]

개별 데이터 값을 데이터의 총합 또는 평균값으로 대체하여 개별 값이 드러나지 않도록 하는 비식별화(데이터 비식별 조치) 기법은?

① 총계처리  ② 가명처리  ③ 데이터 범주화  ④ 데이터 마스킹

<details><summary>정답 및 해설</summary>

**정답: ①**

- **①** 총계처리(aggregation): 개별 값을 총합·평균 등 통계값으로 대체. 예: 학생별 키 → 학급 평균 키. ← 정답
- **②** 가명처리(pseudonymization): 식별 값을 다른 값(가명)으로 대체. 예: 홍길동 → 임꺽정.
- **③** 데이터 범주화(data suppression/categorization): 값을 범주·구간으로 변환. 예: 33세 → 30대.
- **④** 데이터 마스킹(data masking): 식별 값의 일부를 공백·노이즈·기호(*)로 가림. 예: 홍길동 → 홍**.

**출제 포인트:** 비식별화 5대 기법 = 가명처리·총계처리·데이터 삭제·데이터 범주화·데이터 마스킹. 예시 하나씩 짝지어 암기: 가명(이름 바꿈)/총계(평균)/삭제(지움)/범주화(30대)/마스킹(홍**).

**근거:** 총계처리는 데이터의 개별 값을 총합이나 평균 등의 통계값으로 대체하여 개별 데이터의 값이 드러나지 않도록 하는 비식별화 기법이다.
</details>

### Q1-022 [난이도: 상] [태그: 1과목/빅데이터의이해/비식별화기법]

비식별화 기법과 그 처리 방식(세부기술)의 연결로 옳지 <u>않은</u> 것은?

① 가명처리 — 휴리스틱 대체(heuristic pseudonymization): 미리 정한 규칙으로 이름 등을 다른 값으로 대체
② 데이터 마스킹 — 주민등록번호 등 식별자 항목 자체를 원본에서 완전히 삭제
③ 데이터 범주화 — 나이 '33세'를 '30대'라는 구간값으로 변환
④ 총계처리 — 라운딩(rounding)·재배열 등으로 개별 값 대신 통계값을 제공

<details><summary>정답 및 해설</summary>

**정답: ②**

- **①** 옳은 연결. 휴리스틱 대체(가명화)는 가명처리의 세부기술.
- **②** 식별자 항목 자체를 삭제하는 것은 **데이터 삭제** 기법. 마스킹은 삭제가 아니라 값의 일부를 기호(*)·노이즈 등으로 **가리는** 것. ← 정답
- **③** 옳은 연결. 구간값(범주) 변환은 데이터 범주화의 대표 방식.
- **④** 옳은 연결. 라운딩·재배열은 총계처리 계열의 세부기술. ※ 교재별 표기 차이 있음 — 라운딩을 범주화(랜덤 라운딩)로 분류하는 교재도 있다.

**출제 포인트:** "삭제"와 "마스킹"의 구분이 핵심 — 삭제는 항목을 없애는 것, 마스킹은 남기되 가리는 것. 세부기술 매칭형에서는 소속 기법을 바꿔 끼운 선지를 먼저 의심할 것.

**근거:** 데이터 마스킹은 개인 식별에 기여하는 값의 전부 또는 일부를 공백·노이즈·대체 기호 등으로 가려 알아볼 수 없게 하는 비식별화 기법이다.
</details>

### Q1-023 [난이도: 중] [태그: 1과목/빅데이터의이해/마이데이터]

마이데이터(MyData)에 대한 설명으로 옳은 것은?

① 기업이 정보주체의 동의 없이 보유 개인정보를 제3자에게 자유롭게 판매할 수 있도록 하는 제도다.
② 전송요구권은 신용정보법상 금융 분야에서만 인정되며 다른 분야로는 도입되지 않았다.
③ 정보주체가 자신의 개인정보를 본인 또는 제3자에게 전송하도록 개인정보처리자에게 요구할 수 있는 권리(개인정보 전송요구권)에 기반한다.
④ 전송 대상 개인정보는 반드시 종이 문서 형태로 제공되어야 한다.

<details><summary>정답 및 해설</summary>

**정답: ③**

- **①** 반대 설명. 마이데이터의 주체는 기업이 아니라 **정보주체 본인**이며, 본인의 요구·통제가 핵심.
- **②** 금융 분야(신용정보법)에서 먼저 시행된 후, 개인정보 보호법 개정으로 **전 분야 확대**의 법적 근거가 마련되었다.
- **③** 옳은 설명. 마이데이터 = 정보주체 중심의 개인정보 이동·활용, 법적 기반은 **개인정보 전송요구권**. ← 정답
- **④** 전송은 **컴퓨터 등 정보처리장치로 처리 가능한 형태**로 이루어져야 한다. 종이 문서 한정은 반대 설명.

**출제 포인트:** 마이데이터 핵심 3요소 = 주체(정보주체 본인) / 권리(전송요구권) / 형태(기계 판독 가능한 형태). "내(My) 데이터의 이동을 내가 결정한다."

**근거:** 마이데이터는 정보주체가 자신의 개인정보를 본인 또는 제3자에게 전송하도록 요구할 수 있는 개인정보 전송요구권을 기반으로, 정보주체가 개인정보의 이동과 활용을 통제하는 제도다.
</details>

### Q1-024 [난이도: 상] [태그: 1과목/빅데이터의이해/개인정보수집이용원칙]

개인정보 보호법상 개인정보 처리(수집·이용)의 기본 원칙에 대한 설명으로 옳지 <u>않은</u> 것은?

① 적법하게 수집한 개인정보는 당초 수집 목적과 무관한 용도로도 제한 없이 이용할 수 있다.
② 개인정보의 처리 목적을 명확하게 하고, 그 목적에 필요한 최소한의 범위에서 수집하여야 한다.
③ 익명 처리로도 목적을 달성할 수 있는 경우에는 익명 처리를 우선하고, 익명 처리가 곤란하면 가명 처리에 의하도록 한다.
④ 처리 목적에 필요한 범위에서 개인정보의 정확성·완전성·최신성이 보장되도록 하여야 한다.

<details><summary>정답 및 해설</summary>

**정답: ①**

- **①** 개인정보는 **수집 목적의 범위에서** 적합하게 처리해야 하며, 목적 외 용도로 활용하는 것은 원칙적으로 금지된다. "제한 없이 이용"은 틀린 설명. ← 정답
- **②** 옳은 설명. 목적 명확화 + 최소 수집의 원칙.
- **③** 옳은 설명. 익명 처리 우선, 곤란 시 가명 처리의 원칙.
- **④** 옳은 설명. 정확성·완전성·최신성 보장의 원칙.

**출제 포인트:** 기본 원칙의 뼈대 = 목적 명확·최소 수집 / 목적 범위 내 처리(목적 외 이용 금지) / 정확성·최신성 / 안전한 관리 / 익명·가명 처리 우선. 부정형에서는 "제한 없이", "자유롭게" 같은 절대 표현이 들어간 선지가 대개 정답.

**근거:** 개인정보 보호법의 기본 원칙상 개인정보는 처리 목적을 명확히 하여 필요한 최소한의 범위에서 수집하고, 그 목적 범위를 벗어나 활용해서는 안 된다.
</details>
