### Q1-025 [난이도: 하] [태그: 1과목/데이터분석계획/방법론단계수]

분석 방법론과 각 방법론을 구성하는 단계 수의 연결이 모두 옳은 것은?

① KDD 5단계 — CRISP-DM 5단계 — SEMMA 6단계
② KDD 5단계 — CRISP-DM 6단계 — SEMMA 5단계
③ KDD 6단계 — CRISP-DM 5단계 — SEMMA 5단계
④ KDD 4단계 — CRISP-DM 6단계 — SEMMA 6단계

<details><summary>정답 및 해설</summary>

**정답: ②**

- **①** CRISP-DM을 5단계, SEMMA를 6단계로 표기 → 둘 다 틀림.
- **②** KDD 5단계 / CRISP-DM 6단계 / SEMMA 5단계 → 모두 옳음. ← 정답
- **③** KDD는 6단계가 아니라 5단계, CRISP-DM은 5단계가 아니라 6단계.
- **④** KDD는 4단계가 아니라 5단계, SEMMA는 6단계가 아니라 5단계.

**출제 포인트:** 단계 수 암기 = **KDD 5 / CRISP-DM 6 / SEMMA 5**. "5-6-5"로 묶어서 외울 것. ※ 교재별 표기 차이 있음 — KDD를 Fayyad의 원 논문에 따라 9개 프로세스로 세분화해 제시하는 교재도 있으나, 시험 기준 분석 절차는 5단계.

**근거:** KDD는 선택→전처리→변환→데이터 마이닝→해석·평가의 5단계, CRISP-DM은 업무 이해→데이터 이해→데이터 준비→모델링→평가→전개의 6단계, SEMMA는 샘플링→탐색→수정→모델링→평가의 5단계로 구성된 분석 방법론이다.
</details>

### Q1-026 [난이도: 하] [태그: 1과목/데이터분석계획/KDD]

KDD(Knowledge Discovery in Databases) 분석 절차를 순서대로 옳게 나열한 것은?

① 데이터셋 선택 → 데이터 전처리 → 데이터 변환 → 데이터 마이닝 → 해석·평가
② 데이터셋 선택 → 데이터 변환 → 데이터 전처리 → 데이터 마이닝 → 해석·평가
③ 데이터 전처리 → 데이터셋 선택 → 데이터 변환 → 해석·평가 → 데이터 마이닝
④ 데이터셋 선택 → 데이터 전처리 → 데이터 마이닝 → 데이터 변환 → 해석·평가

<details><summary>정답 및 해설</summary>

**정답: ①**

- **①** 선택(Selection) → 전처리(Preprocessing) → 변환(Transformation) → 데이터 마이닝(Data Mining) → 해석·평가(Interpretation/Evaluation). ← 정답
- **②** 전처리와 변환의 순서가 바뀜. 잡음·이상값을 정제(전처리)한 뒤에 분석 목적에 맞게 변수를 생성·축소(변환)한다.
- **③** 선택이 가장 먼저다. 분석 대상 데이터셋을 골라야 전처리가 가능하며, 마이닝 후에 해석·평가가 온다.
- **④** 변환은 데이터 마이닝 이전의 준비 작업이다. 마이닝 후에 변환하는 절차는 없다.

**출제 포인트:** KDD 5단계 = "**선-전-변-마-해**"로 암기. 전처리(정제)가 먼저, 변환(변수 생성·차원 축소)이 나중.

**근거:** KDD는 데이터베이스에서 유용한 지식을 발견하는 프로세스로, 데이터셋 선택→전처리→변환→데이터 마이닝→해석·평가의 5단계로 수행된다.
</details>

### Q1-027 [난이도: 중] [태그: 1과목/데이터분석계획/CRISP-DM]

CRISP-DM 방법론의 6단계를 순서대로 옳게 나열한 것은?

① 데이터 이해 → 업무 이해 → 데이터 준비 → 모델링 → 평가 → 전개
② 업무 이해 → 데이터 준비 → 데이터 이해 → 모델링 → 평가 → 전개
③ 업무 이해 → 데이터 이해 → 데이터 준비 → 모델링 → 평가 → 전개
④ 업무 이해 → 데이터 이해 → 데이터 준비 → 평가 → 모델링 → 전개

<details><summary>정답 및 해설</summary>

**정답: ③**

- **①** 업무 이해가 데이터 이해보다 먼저다. 비즈니스 목적 파악이 출발점.
- **②** 데이터 이해가 데이터 준비보다 먼저다. 데이터를 파악(수집·탐색)한 뒤에 정제·가공한다.
- **③** 업무 이해(Business Understanding) → 데이터 이해(Data Understanding) → 데이터 준비(Data Preparation) → 모델링(Modeling) → 평가(Evaluation) → 전개(Deployment). ← 정답
- **④** 모델링이 평가보다 먼저다. 모델을 만든 뒤 비즈니스 목적 달성 여부를 평가한다.

**출제 포인트:** CRISP-DM 6단계 = "**업-데이-데준-모-평-전**". 단계 간 피드백(업무 이해↔데이터 이해, 데이터 준비↔모델링, 평가→업무 이해)이 존재하는 반복적 모형이라는 점도 함께 기억.

**근거:** CRISP-DM(Cross Industry Standard Process for Data Mining)은 업무 이해→데이터 이해→데이터 준비→모델링→평가→전개의 6단계로 구성된 계층적·반복적 데이터 마이닝 표준 방법론이다.
</details>

### Q1-028 [난이도: 중] [태그: 1과목/데이터분석계획/CRISP-DM]

다음 중 CRISP-DM 방법론의 6단계에 해당하지 <u>않는</u> 것은?

① 업무 이해(Business Understanding)
② 데이터 준비(Data Preparation)
③ 전개(Deployment)
④ 데이터 변환(Transformation)

<details><summary>정답 및 해설</summary>

**정답: ④**

- **①** 업무 이해: CRISP-DM의 1단계. 비즈니스 관점의 목적·요구사항 파악.
- **②** 데이터 준비: CRISP-DM의 3단계. 정제·통합·포맷팅 등 분석용 데이터셋 구성.
- **③** 전개: CRISP-DM의 6단계. 모델을 실제 업무에 적용하고 유지보수 계획 수립.
- **④** 데이터 변환은 CRISP-DM이 아니라 **KDD의 3단계**다. CRISP-DM에서는 변환 작업이 '데이터 준비' 단계 안에 포함된다. ← 정답

**출제 포인트:** 단골 함정 = KDD 단계(선택·전처리·변환)를 CRISP-DM 선지에 끼워 넣는 바꿔치기. "변환(Transformation)이 독립 단계면 KDD, 준비(Preparation)에 흡수돼 있으면 CRISP-DM."

**근거:** CRISP-DM의 6단계는 업무 이해, 데이터 이해, 데이터 준비, 모델링, 평가, 전개이며 데이터 변환은 KDD 분석 절차의 단계명이다.
</details>

### Q1-029 [난이도: 중] [태그: 1과목/데이터분석계획/CRISP-DM4계층]

CRISP-DM의 4계층(레벨) 구조를 최상위 계층부터 순서대로 옳게 나열한 것은?

① 단계 → 세분화 태스크 → 일반화 태스크 → 프로세스 실행
② 단계 → 일반화 태스크 → 세분화 태스크 → 프로세스 실행
③ 프로세스 실행 → 단계 → 일반화 태스크 → 세분화 태스크
④ 일반화 태스크 → 단계 → 세분화 태스크 → 프로세스 실행

<details><summary>정답 및 해설</summary>

**정답: ②**

- **①** 일반화 태스크가 세분화 태스크보다 상위다. 일반적 활동을 먼저 정의하고 이를 구체화한다.
- **②** 단계(Phases) → 일반화 태스크(Generic Tasks) → 세분화 태스크(Specialized Tasks) → 프로세스 실행(Process Instances). ← 정답
- **③** 프로세스 실행은 최하위 계층이다. 실제 프로젝트에서 수행된 기록이 가장 구체적 수준.
- **④** 단계가 최상위 계층이다. 일반화 태스크는 단계를 구성하는 하위 요소.

**출제 포인트:** 4계층 = "**단-일-세-프**"(위→아래). 위로 갈수록 추상적·일반적, 아래로 갈수록 구체적·개별 프로젝트 수준.

**근거:** CRISP-DM은 최상위의 단계(Phases), 각 단계를 구성하는 일반화 태스크(Generic Tasks), 이를 구체화한 세분화 태스크(Specialized Tasks), 실제 수행 기록인 프로세스 실행(Process Instances)의 4계층 구조로 이루어진 계층적 프로세스 모델이다.
</details>

### Q1-030 [난이도: 중] [태그: 1과목/데이터분석계획/SEMMA]

SAS사가 주도한 SEMMA 방법론에 대한 설명으로 옳지 <u>않은</u> 것은?

① 업무 이해(Business Understanding) 단계에서 출발하여 비즈니스 문제 정의를 가장 강조한다.
② 수정(Modify) 단계에서는 변수의 변환·생성·선택 등 데이터 가공을 수행한다.
③ 탐색(Explore) 단계에서는 시각화와 기초 통계를 통해 데이터의 패턴을 파악한다.
④ 샘플링(Sample) → 탐색(Explore) → 수정(Modify) → 모델링(Model) → 평가(Assess)의 5단계로 구성된다.

<details><summary>정답 및 해설</summary>

**정답: ①**

- **①** 업무 이해에서 출발하는 것은 **CRISP-DM**이다. SEMMA는 분석 대상 데이터의 샘플링에서 출발하는 **기술(통계·모델링) 중심** 방법론으로, 비즈니스 이해 단계가 명시적으로 없다. ← 정답
- **②** 옳은 설명. Modify = 변수 변환·생성·선택, 데이터 가공.
- **③** 옳은 설명. Explore = 시각화·기초 통계로 패턴·이상값 탐색.
- **④** 옳은 설명. S-E-M-M-A 5단계.

**출제 포인트:** SEMMA는 머리글자 그대로 **S**ample-**E**xplore-**M**odify-**M**odel-**A**ssess. "비즈니스에서 출발하면 CRISP-DM, 데이터(샘플)에서 출발하면 SEMMA"로 구분.

**근거:** SEMMA는 SAS사가 주도한 데이터 마이닝 방법론으로 샘플링→탐색→수정→모델링→평가의 5단계로 구성되며, 데이터에서 출발하는 기술 중심적 접근이 특징이다.
</details>

### Q1-031 [난이도: 상] [태그: 1과목/데이터분석계획/방법론비교]

KDD, CRISP-DM, SEMMA 세 방법론의 단계 대응에 대한 설명 중 옳은 것만 모두 고른 것은?

- ㄱ. KDD의 '데이터 변환' 단계는 CRISP-DM의 '데이터 준비' 단계에, '데이터셋 선택' 단계는 '데이터 이해' 단계에 대응한다.
- ㄴ. CRISP-DM의 '업무 이해'에 대응하는 단계는 SEMMA에 명시적으로 존재하지 않는다.
- ㄷ. KDD의 '해석·평가'는 CRISP-DM의 '평가', SEMMA의 '평가(Assess)'와 대응한다.
- ㄹ. SEMMA의 '샘플링(Sample)'은 CRISP-DM의 '전개(Deployment)'에 대응한다.

① ㄱ, ㄴ  ② ㄴ, ㄷ, ㄹ  ③ ㄱ, ㄴ, ㄷ  ④ ㄱ, ㄷ, ㄹ

<details><summary>정답 및 해설</summary>

**정답: ③**

- **ㄱ (O)** 표준 대응표(Azevedo & Santos 비교표 기반) 기준으로 KDD의 데이터셋 선택·데이터 전처리는 CRISP-DM의 **데이터 이해**에, 데이터 변환은 **데이터 준비**에 대응한다.
- **ㄴ (O)** SEMMA는 데이터 샘플링에서 출발하는 기술 중심 방법론으로, 비즈니스 이해 단계가 없다.
- **ㄷ (O)** 세 방법론 모두 마지막에 결과 해석·평가 단계를 둔다(KDD 해석·평가 / CRISP-DM 평가 / SEMMA Assess).
- **ㄹ (X)** 샘플링은 분석용 데이터를 추출하는 활동으로 **데이터 준비·선택 계열**에 대응한다. 전개는 모델의 실무 적용 단계로 성격이 전혀 다르며, SEMMA에는 전개에 해당하는 단계가 없다.

따라서 옳은 것은 ㄱ, ㄴ, ㄷ → **③**. (①은 옳은 ㄷ 누락, ②·④는 틀린 ㄹ 포함)

**출제 포인트:** 대응 관계 축 = "데이터 파악(선택·전처리 = 데이터 이해)", "데이터 가공(변환 = 데이터 준비 = Sample·Modify)", "모델 구축(마이닝 = 모델링 = Model)", "결과 확인(해석·평가 = 평가 = Assess)". 전개(Deployment)는 **CRISP-DM에만 있는 단계**라는 점이 핵심.

**근거:** KDD·CRISP-DM·SEMMA는 데이터 준비→모델링→평가라는 공통 흐름을 공유하지만, 업무 이해와 전개 단계는 CRISP-DM에만 명시적으로 존재한다.
</details>

### Q1-032 [난이도: 하] [태그: 1과목/데이터분석계획/하향식접근]

하향식(top-down) 분석 과제 발굴 절차를 순서대로 옳게 나열한 것은?

① 문제 정의 → 문제 탐색 → 해결방안 탐색 → 타당성 검토
② 문제 탐색 → 문제 정의 → 해결방안 탐색 → 타당성 검토
③ 문제 탐색 → 해결방안 탐색 → 문제 정의 → 타당성 검토
④ 타당성 검토 → 문제 탐색 → 문제 정의 → 해결방안 탐색

<details><summary>정답 및 해설</summary>

**정답: ②**

- **①** 탐색이 정의보다 먼저다. 비즈니스 모델 등에서 문제 후보를 발굴(탐색)한 뒤 데이터 분석 문제로 변환(정의)한다.
- **②** 문제 탐색(Problem Discovery) → 문제 정의(Problem Definition) → 해결방안 탐색(Solution Search) → 타당성 검토(Feasibility Study). ← 정답
- **③** 문제를 정의해야 그 문제의 해결방안을 탐색할 수 있다. 순서가 바뀜.
- **④** 타당성 검토는 도출된 해결방안에 대해 마지막에 수행한다.

**출제 포인트:** 하향식 4단계 = "**탐-정-해-타**". 문제 탐색에서는 비즈니스 모델 캔버스·분석 유스케이스 활용, 문제 정의에서는 비즈니스 문제를 데이터 분석 문제로 변환, 타당성 검토는 경제적 타당성과 데이터·기술적 타당성 평가.

**근거:** 하향식 접근은 문제가 주어진 상태에서 문제 탐색→문제 정의→해결방안 탐색→타당성 검토의 순서로 해법을 찾아가는 분석 과제 발굴 방식이다.
</details>

### Q1-033 [난이도: 중] [태그: 1과목/데이터분석계획/상향식접근]

분석 과제 발굴의 상향식(bottom-up) 접근과 관련된 설명으로 옳지 <u>않은</u> 것은?

① 상향식 접근은 문제 정의 자체가 어려운 경우 데이터를 기반으로 통찰(insight)을 도출하는 방식이다.
② 프로토타이핑(prototyping) 접근은 일단 분석을 시도하고 결과를 확인하며 반복적으로 개선하는 시행착오 방식이다.
③ 디자인 씽킹(design thinking)은 상향식의 발산(diverge) 단계와 하향식의 수렴(converge) 단계를 반복하여 최적의 방안을 도출한다.
④ 상향식 접근은 문제가 명확히 주어진 상태에서 해법을 찾아가는 전통적 분석 과제 발굴 방식이다.

<details><summary>정답 및 해설</summary>

**정답: ④**

- **①** 옳은 설명. 문제를 사전에 정의하기 어려울 때 데이터 자체에서 인사이트를 발굴.
- **②** 옳은 설명. 프로토타이핑 = "먼저 분석 시도 → 결과 확인 → 반복 개선". 사용자가 요구사항을 명확히 모를 때 유용.
- **③** 옳은 설명. 디자인 씽킹은 발산(상향식)과 수렴(하향식)을 반복하는 상호보완적 접근.
- **④** 문제가 명확히 주어진 상태에서 해법을 찾는 것은 **하향식** 접근이다. 상향식은 문제 정의가 어려운 상황에서 데이터로부터 출발한다. ← 정답

**출제 포인트:** "문제가 주어짐 → 하향식(수렴적) / 문제 정의 곤란 → 상향식(발산적)". 하향식·상향식 정의를 서로 바꿔치기하는 선지가 단골.

**근거:** 상향식 접근은 문제의 정의 자체가 어려운 경우 데이터를 기반으로 문제를 지속적으로 개선하면서 통찰을 도출하는 분석 과제 발굴 방식이다.
</details>

### Q1-034 [난이도: 상] [태그: 1과목/데이터분석계획/성숙도준비도]

A기업을 진단한 결과, 분석에 필요한 데이터·인력·조직 등 준비도(readiness)는 높지만 실제 분석 업무를 수행해 본 경험이 거의 없어 성숙도(maturity)는 낮은 것으로 나타났다. 분석 수준 진단의 사분면 분석에서 A기업이 속하는 유형은?

① 준비형  ② 정착형  ③ 도입형  ④ 확산형

<details><summary>정답 및 해설</summary>

**정답: ③**

- **①** 준비형: 준비도·성숙도 **모두 낮음** → 분석을 위한 사전 준비가 필요한 기업.
- **②** 정착형: **준비도는 낮으나** 조직·인력 등을 제한적으로 사용하며 성숙도가 어느 정도 있는 기업 → 1차적으로 정착이 필요.
- **③** 도입형: **준비도는 높으나 성숙도는 낮음** → 데이터 분석을 바로 도입할 수 있는 기업. A기업이 해당. ← 정답
- **④** 확산형: 준비도·성숙도 **모두 높음** → 지속적 확산이 가능한 기업.

**출제 포인트:** 사분면 4유형 = 준비도·성숙도 (低·低)=**준비형**, (低·高)=**정착형**, (高·低)=**도입형**, (高·高)=**확산형**. 함께 나오는 성숙도 4단계는 **도입→활용→확산→최적화**(도입: 분석 시작·환경 구축, 활용: 분석 결과를 업무에 적용, 확산: 전사 차원 관리·공유, 최적화: 분석의 진화로 혁신·가치 창출).

**근거:** 분석 수준 진단은 분석 준비도와 분석 성숙도 두 축의 사분면으로 조직을 준비형·정착형·도입형·확산형의 4개 유형으로 구분하는 진단 방법이다.
</details>

### Q1-035 [난이도: 중] [태그: 1과목/데이터분석계획/마스터플랜우선순위]

분석 마스터플랜 수립 시 분석 과제의 우선순위 평가에 대한 설명으로 옳지 <u>않은</u> 것은?

① 난이도(difficulty)는 전략적 중요도와 목표 가치(KPI)에 따라 평가한다.
② 시급성이 높고 난이도가 쉬운 과제가 가장 우선적으로 추진된다.
③ ROI 관점에서 빅데이터의 3V(규모·다양성·속도)는 투자비용 요소로서 난이도와 연결된다.
④ 난이도는 데이터 획득·저장·가공 비용과 분석 수준 등을 고려하여 평가하며, 기업 상황에 따라 조율할 수 있다.

<details><summary>정답 및 해설</summary>

**정답: ①**

- **①** 전략적 중요도와 목표 가치에 따라 평가하는 것은 **시급성(urgency)**이다. 난이도는 비용·기술 등 실행 측면의 기준. ← 정답
- **②** 옳은 설명. 시급성 高 + 난이도 易 과제가 최우선 추진 대상.
- **③** 옳은 설명. ROI 관점에서 3V(Volume·Variety·Velocity)는 투자비용(Investment) 요소 → 난이도, 가치(Value)는 비즈니스 효과 요소 → 시급성과 연결.
- **④** 옳은 설명. 난이도 = 데이터 획득·저장·가공 비용 + 분석 적용 비용 + 분석 수준. 기업 여건에 따라 난이도를 조율(易↔難)해 우선순위를 조정할 수 있다.

**출제 포인트:** 우선순위 2대 기준 = **시급성(전략적 중요도·목표 가치 → Value)** / **난이도(비용·기술 → 3V)**. "중요하면 시급성, 비싸고 어려우면 난이도." ※ 교재별 표기 차이 있음 — 사분면 번호(I~IV)와 축 배치는 교재마다 다르게 그려지므로 번호보다 "시급성 높고 쉬운 과제부터"라는 원리로 기억할 것.

**근거:** 분석 마스터플랜의 과제 우선순위는 전략적 중요도와 목표 가치로 평가하는 시급성, 그리고 데이터 비용과 분석 수준으로 평가하는 난이도의 두 기준을 고려하여 결정한다.
</details>

### Q1-036 [난이도: 하] [태그: 1과목/데이터분석계획/분석기획고려사항]

빅데이터 분석 기획 단계에서 1차적으로 고려해야 할 사항으로 가장 적절한 것은?

① 분석 모형에 적용할 알고리즘의 하이퍼파라미터 튜닝 전략 수립
② 분석 결과 대시보드의 화면 배치와 차트 종류 확정
③ 분석 서버의 CPU 코어 수와 메모리 용량 확정
④ 활용 가능한 데이터의 존재 여부·유형 확인과 장애요소에 대한 사전계획 수립

<details><summary>정답 및 해설</summary>

**정답: ④**

- **①** 하이퍼파라미터 튜닝은 **모델링(분석 수행) 단계**의 세부 작업. 기획 단계의 고려사항이 아님.
- **②** 대시보드 설계는 **결과 시각화·전개 단계**의 작업. 기획 단계에서 확정할 사항이 아님.
- **③** 서버 사양 확정은 **시스템 구현 단계**의 세부사항. 기획 단계에서는 가용성 수준만 검토.
- **④** 기획 시 고려사항 = **가용 데이터**(존재 여부·유형), **적절한 유스케이스 탐색**, **장애요소에 대한 사전계획 수립**. ← 정답

**출제 포인트:** 분석 기획 시 고려사항 3가지 = "**데이터(가용성) · 유스케이스(활용 방안) · 장애요소(사전계획)**". 데이터 유형(정형·반정형·비정형)에 따라 수집·저장·분석 방식이 달라지므로 데이터 확인이 출발점.

**근거:** 분석 기획 시에는 분석에 활용 가능한 데이터의 확보 여부와 유형, 기존 유스케이스의 탐색·활용, 그리고 장애요소에 대한 사전계획 수립을 우선적으로 고려해야 한다.
</details>
